# 已知限制

如实列出。**这不是「待优化项」清单，是会影响你使用方式的行为**，请在接入前读完。

---

## 一、平台行为，改不了

### 授权时要绑定一个企业微信「机器人」

扫码授权后，企业微信会让你选择：**新建一个机器人**，或**绑定一个已有的机器人**。

首次授权时你名下没有机器人，只能新建。之后再授权，就可以选择绑定原来那个。

**为什么这个选择很重要**：写操作只认机器人所有权 —— 一个机器人**不拥有另一个机器人创建的对象**。

| 重新授权时选择 | 对旧文档 / 表格 / 日程的编辑权 |
|---|---|
| **绑定原有机器人** | 保住（机器人没变，所有权不变） |
| 新建机器人 | **失去**，且不可恢复 |

所以：**重新授权时选「绑定已有机器人」，并选中原来那一个。**

> 上表第一行是从两条已验证的事实推出的：①写操作按 `bot_id` 判定所有权；②同一个人多次授权
> 曾拿到不同 `bot_id`，这正是写权限断裂的原因。绑定同一个机器人时 `bot_id` 不变，判定结果
> 自然不变。**但「绑定已有机器人」是否确实沿用同一个 `bot_id`（而非新建一个再关联），本项目
> 尚未实测。** 绑定后可用 `scripts/probe-creds.sh` 打出 `bot_id` 与授权前对比，一致即确认。

**缓解措施（已实现）**：
- 服务端签发 refresh token，令牌到期由客户端自动续期，**根本不需要重新授权**，因此也不涉及机器人选择。
- 服务端按真人企业微信身份去重：认出老用户且旧凭证仍可用时**复用原凭证槽位**，
  重新授权因此变成幂等操作。

**残留代价**：首次授权必然新建一个机器人 —— 「扫码前无从得知你是谁」是鸡生蛋问题，无法消除。
每个使用者名下预期有**一个**机器人；如果多于一个，说明某次重新授权时选了新建。

### 读写权限不对称

平台声明：可以读取授权人创建或拥有的数据，但**只能写入或修改机器人自己创建或拥有的数据**。

实测比字面宽一些：新建对象成功且授权人可见可用；`message.send` 实际以**授权人本人身份**发出
（收件人看到的是授权人，不是机器人）。但**修改授权人在授权前已创建的对象**未验证，请勿假设可行。

### 删除机器人会立刻让对应凭证失效

在企业微信里删掉某个机器人后，服务端对应的凭证仍在，但调用会返回
`errcode 853005 cli token invalid`。**密钥存在 ≠ 机器人存在**。
排查凭证问题时请先确认是否有人删过机器人。

`scripts/probe-creds.sh` 可批量探测每条凭证是否仍然有效。

### 授权只能扫码

`wecom-cli` 的 `--manual` 模式显式检测 TTY 并拒绝（错误码 `893001`），
没有非交互注入凭证的入口。因此授权流程必须由长驻容器承载，不能塞进 Lambda 的请求响应模型。

## 二、客户端侧限制

### Quick Suite

- 需 **Enterprise 订阅**；完整功能仅在以下 7 个区域可用（`us-east-1` `us-west-2`
  `ap-northeast-1` `ap-southeast-2` `eu-central-1` `eu-west-1` `eu-west-2`），
  部署区域必须从中选择。
- **工具列表注册后是静态的**。服务端新增工具后，必须删掉 integration 重建才能生效。
- 单次 MCP 操作**固定 60 秒超时**，超时返回 HTTP 424。本服务实测调用 3–4 秒，余量充足。
- 单个 MCP 连接**最多 100 个工具**。本服务暴露 37 个。
- **不支持自定义 HTTP 头**，所以云端必须走 OAuth，不能用固定 Bearer。
- 续期是**反应式**的：令牌到期后不主动刷新，等下一次调用撞到 401 才换，
  实测存在约 4 分钟的失败窗口。已把 access token 设为 30 天以把该窗口降到每 30 天一次。
- 连接器创建失败后**不能原地重试**，必须删掉重建。

### Quick Desktop

Desktop 与 Quick 云端是同一个账号，**管理员在云端建的 MCP 集成会自动出现在 Desktop 里** ——
走这条路时 Desktop 与云端行为一致（OAuth 扫码、自动续期），上面那些约束同样适用，没有额外限制。

只有当你**在 Desktop 里自行添加**时才受限：Desktop 自己的 `MCP Servers → Remote` 表单按 AWS
官方文档只有 `Name / URL / Token / Description / Timeout`，**没有 OAuth 流程**。这种方式下令牌
30 天有效且**没有**自动续期机制，到期需重新走 `/authorize/self` 自助获取。

> 「云端建的会自动同步到 Desktop」：官方文档在 Web Connectors 一节明确写了
> 「Connectors added on the web appear automatically in the desktop application」，
> 但**未针对 MCP 集成单独声明**。实际同步行为已在真实环境观察到。

## 三、本服务尚未实现

| 项 | 影响 |
|---|---|
| Skill 引擎（`wecom_list_skills` / `wecom_get_skill`） | 复杂多步操作缺少编排指引，模型需自行摸索调用顺序 |
| `wecom_discover` 按 schema 指纹去重 | 94 个方法实际只有 74 个唯一请求结构，工具发现有冗余 |
| 跨容器实例的凭证写入 CAS | 现仅单实例内串行化。同一用户在多实例并发写凭证理论上可能互相覆盖，已有检测告警但未阻断 |
| `/register` 方法级限流 | DCR 注册端点开放无鉴权（伪造不出合法 `client_id`，但可被刷） |
| 不活跃凭证保活 | 长期不使用的凭证是否会被企业微信侧失效**未验证**。若会，需定时任务触发容器空转 |
| 告警订阅 | SNS 主题已创建但**默认零订阅**，`CRITICAL` 告警发不出去。部署后须自行订阅 |
| 告警与 Dashboard 覆盖 | 仅 3 条关键告警（凭证回写丢失、OAuth 错误、Runtime 异常），缺 p95 延迟 / 并发 / 限流等 |

## 四、运维须知

- **SSM 里的签名根密钥绝不能重建**。它派生出所有令牌的签名子密钥，重建会让**全部已发令牌立即失效**，
  所有用户需重新授权（重新授权时选「绑定已有机器人」可避免机器人数量增长与写权限断裂）。
  `deploy.sh` 只在其不存在时创建，已做保护。
- **用户凭证的 KMS CMK 是 `RETAIN`**，删栈不会一起删除，需要单独清理。
- **`update-function-configuration` 会替换整个环境变量集合**，手工改一个变量会抹掉其余。
  改配置请走 `deploy.sh`，它一次重传完整集合。
- 撤销某用户 = 删除其 Secret。请注意这是**撤销**而非重置：该用户需重新授权。
  提醒他授权时选「绑定已有机器人」，否则会失去对旧产物的写权限。
